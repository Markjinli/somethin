先更正一处

这一页的头号发现,是一个足以骗过工具的陷阱

更正

mihomo 的核心不是 MIT,是 GPL-3.0

早期版本的本页写过"核心是 MIT,所以 GPL 义务只来自客户端外壳"。这条是错的。

原因是一个很隐蔽的坑:MetaCubeX/mihomo 的默认分支是 main,而 main 里不是代理核心 —— 是一个也叫 mihomo 的 Python 包(崩坏:星穹铁道 API 客户端),MIT 协议。真正的 Go 核心在 Meta 分支上,是 GPL-3.0。

GitHub 的许可证徽章和 /repos/<owner>/<repo>/license 接口都只读默认分支,所以两边都报 MIT。

同一个坑还套着第二层。chen08209/Clash.Meta(FlClash 的核心 fork)默认分支也是 main,同样显示 MIT;但 FlClash 实际用的是 FlClash 分支,是 GPL-3.0。

可以 / 不可以

GPL-3.0-only 下,你能做什么、不能做什么 —— 两家完全一样

可以

  • + 商用无任何限制,可以卖。
  • + 任意修改改多少都行,不需要告知任何人。
  • + 闭源「开发」自己内部改、不对外发,完全合法,没有开源义务。
  • + 收费分发可以收钱 —— 但必须同时给源码。

不可以

  • − 闭源分发二进制最容易踩的坑。只要把编译产物发出去(哪怕免费),就必须提供完整对应源码,而且你的改动也必须是 GPL-3.0-only。
  • − 加附加限制不能加"禁止商用""禁止修改"这类条款。GPL 不允许在下游收紧。
  • − 上 App StoreGPL 与苹果商店的使用限制条款冲突。两家都走不了这条路。
  • − 名字里带 mihomo上游附加条款,见下一节。
  • − 连带分发那两个专有组件见"两家风险面"。两个都要清掉。

补充一句边界情况:SaaS 不分发不触发 GPL(改完只在自己服务器上跑,没有义务开源)。但这个例外对代理客户端没有意义 —— 这东西的价值就在于发给用户。

命名限制

mihomo 在 GPL-3.0 之外附加的条款,对你起名有直接约束

上游附加条款

This software is released under the GPL-3.0 license.

In addition, any downstream projects not affiliated with MetaCubeX shall not contain the word mihomo in their names.

—— MetaCubeX/mihomo 的 Meta 分支 README,紧随许可证声明之后

这是 GPL-3.0 之外的附加限制。GPL §7 是否允许这种条款在社区里有争议,至今没有法律裁决。所以它的实际效力不确定,但风险是真实的 —— 因为上游有实际的施压手段。

这不是假设,已经真打过一架。下游项目 Mihomo Party 拒绝改名,核心团队公开发话并一度威胁停止核心开发:

任何名字中包含 mihomo 字样的 GUI 客户端均与本项目无关,且违反授权协议,请勿使用这些恶意软件

—— MetaCubeX 官方 Telegram 频道

结局是 Mihomo Party 改名成了 Clash Party(仓库迁到 mihomo-party-org/clash-party,站点迁到 clashparty.org),核心开发随后恢复。

对你的实际约束:

  • 必须避开 你的 fork 名字里绝不能出现 mihomo。注意限制的是 mihomo 这个词,不是 "Clash" —— 我找遍了,没有任何针对 "Clash" 这个词的商标政策或名称限制。
  • FlClash 现状 干净。它用 core/Clash.Meta 作子模块目录名,项目名也不含 mihomo。
  • Verge 现状 擦边。项目名不含 mihomo,但它捆绑的核心二进制叫 verge-mihomo —— 含了那个词。严格解释下处于灰色地带,不过上游从未对 Verge 表态。

血统时间线

两家都接得干净 —— 没有版权阴影

这一节回答一个不写在许可证里、但真实影响长期风险的问题:这两个项目的来源清不清白? 结论是:清白的。没有 DMCA,没有授权纠纷,没有原作者抗议。

  • 2018-09 Dreamacro/clash 以 MIT 发布(经 Go module proxy 查得 v0.7.1 的 LICENSE)
  • 2020 起 clash 转为 GPL-3.0,此后未再变更
  • 2021-05-20 Clash.Meta 仓库建立(即后来的 mihomo,仓库重命名,创建日期保留)
  • 2023-08-15 FlClash 建立。不是任何项目的 GitHub fork,作者此前也无同类项目
  • 2023-11-03 生态删库潮。Dreamacro/clash 被作者本人删除(不是 DMCA);zzzgydi/clash-verge 被作者本人 archive(21,922 star)。起因是前一天另一位开发者宣布停止更新,事件在社交平台发酵,多个项目主动避风头
  • 2023-11-21 Clash Verge Rev 建立 —— 原版 archive 后 18 天。README 以"Continuation of Clash Verge"自我定位,致谢名单第一位是原作者
  • 2023-12-21 chen08209 建立核心 fork chen08209/Clash.Meta
  • 2025-02 前后 mihomo 加入命名限制条款 → 与 Mihomo Party 公开冲突 → 对方改名 Clash Party → 争议平息
  • 2026-09-22 本页数据核实日

两个值得注意的点。其一,zzzgydi(原版 Clash Verge 作者)在 Rev 仓库里是最大贡献者(1022 commits) —— 这本身就说明交接是和平的。其二,从头到尾找不到原作者对 fork 的任何表态,无论支持还是反对;也找不到任何针对这两家的 GPL 投诉、DMCA 或授权纠纷。

唯一需要标注的是:Dreamacro/clash 被删的原因从未被公开解释过。流传的说法(监管压力、身份暴露)都被来源明确标为未经证实的传言,且没有开发者被捕。这件事没有给下游留下任何已知的版权主张。

两家风险面

许可证既然对等,差异就全在这些地方

下面这些跟许可证无关,是接手一个代码库时真正会绊到你的东西。这一节是两家唯一实质拉开差距的地方。

  • FLCLASH · 第三方专有组件 · 更要紧 windows/EnableLoopback.exe —— Progress Software Corporation 的工具,Copyright ©2003-2020,All rights reserved,闭源,有有效代码签名。已提交进 git,随 Windows 版出货,并且被 lib/views/tools.dart:204 以提权方式实际执行。"All rights reserved" 意味着没有任何再分发授权。要清掉得连带删功能或换实现。
  • VERGE · 第三方专有组件 · 好处理 src-tauri/assets/fonts/SF-Pro.ttf —— 苹果 SF Pro,23 MB,字体内部嵌着的授权原文明确写着 "You may not embed the Apple Font in any software programs or other products",且要求使用者是注册苹果开发者。但我核实过它零引用:代码里没有、resources 是空的、没有 Info.plist 声明 —— 不进分发包。删掉这一个文件问题即消失。
  • 版权集中度 FlClash:3 个贡献者(一人 231/233 commits,实质单人项目)。Verge:166 个贡献者。两家都没有 CLA,所以两家法律上都无法单方面改许可证 —— 但 FlClash 只需谈 1 个人,Verge 要谈 166 个。
  • 单点风险 FlClash 是单人项目,作者弃坑即终止。Verge 有 166 人 + 长尾,谁也拿不走,生态韧性明显更强。
  • 许可证声明卫生 Verge 在 manifest 里明示 GPL-3.0-only,规矩。FlClash 没有任何 manifest 声明,且 plugins/proxy/LICENSE 与 plugins/rust_api/LICENSE 的内容是字面一句 TODO: Add your license here.(Flutter 插件模板占位符,从未填)。法律上仓库根的 GPL-3.0 默认覆盖全部,不是陷阱,但说明卫生粗放。

怎么选

许可证对等,所以选型看技术栈和长期打算

如果你的改动要分发(发二进制,免费也算),许可证层面两家完全等价,按下面的条件选:

熟 Dart / Flutter,想要一个仓库搞定全部(含提权服务、含自己 fork 的核心) FlClash
熟 Rust / Tauri,想要长期有人维护、生态大 Verge
想将来有一天谈商业授权或改许可证 FlClash
想向上游提 PR、影响项目方向 Verge
不想碰专有二进制 —— 倾向删一个文件就完事 Verge

如果改动只在自己内部署、或者你本来就打算开源,那两家都行,纯按技术栈选。

不管选哪个,动手前先做这几件事:

  • 选 FLCLASH删掉 windows/EnableLoopback.exe 和 lib/views/tools.dart 里那个入口,或换成自己的 UWP 回环实现。
  • 选 VERGErm src-tauri/assets/fonts/SF-Pro.ttf。它没被引用,删了不影响构建。
  • 两家都要给项目起名时避开 mihomo 这个词。加上 GPL-3.0 的 LICENSE,并把改动的源码公开。
